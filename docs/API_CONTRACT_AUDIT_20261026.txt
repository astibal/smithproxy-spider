Findings to close before merge
-----------------------------
1. Public documents contradict the implemented Translate/strict support.

   README.md:596 says TRANSLATE and strict are future work; :639 repeats that
   assumption. docs/FIRST_CLASS_API_DESIGN.md:300 and :323-329 make the same
   claim in the binding design document. Yet README's introduction and
   docs/H2_TRANSLATE_LIVE.md describe implemented live Translate, and backend
   routing, strict control and real-proxy tests implement it.

   Required correction: distinguish the current bounded H2 Translate support
   from deferred general translation, compression and HOLD/REWRITE failure
   protection. Preserve historical POC descriptions as explicitly historical.

2. README live rewrite examples omit the connection-start guard/reservation.

   The H2 example at README.md:564 iterates api.message.parts unconditionally.
   In setup, api.message is None. The H1 snapshot and live hold examples have
   the same setup issue. Unlike the cookbook, README has no request_rewrite()
   guard explaining the required live deployment setup.

   Reproduced by extracting the exact H2 README Python block and invoking the
   real sandboxed worker through tests/inspection_cookbook_test.py::run:
     fixture('setup'):
       AttributeError: 'NoneType' object has no attribute 'parts'
     fixture('h2'), webhook_control.rewrite=false:
       CommitException: Length-changing rewrite was not reserved at connection-start

   Required correction: make live examples self-contained or label them as
   content-only fragments with an unavoidable setup prerequisite. Add tests
   executing README live examples through setup and content, not only fixtures
   with absent capability metadata. Existing cookbook tests do not cover README.

3. General failure wording incorrectly includes active Translate.

   docs/INSPECTION_COOKBOOK.md:170-171 says script failures are fail-open and
   strict/drop remain TODO. This is true of ordinary Rewrite hold failure
   protection, not of an already active Translate connection.

   Actual boundary:
   - before successful Translate activation, ordinary script failure can leave
     the original callback unchanged under regular policy;
   - after activation, the backend pins deployment/version, requires strict
     mode and consecutive sequence, and returns HTTP 503 on failure;
   - strict proxy closes instead of forwarding unprocessed current content;
   - ordinary Rewrite hold remains deliberately fail-open on loss/failure.

   Evidence: src/inspection.cpp:539-562, :610-625; src/webhook.cpp:145-152;
   Smithproxy src/proxy/mitmproxy.cpp:1450; docs/H2_TRANSLATE_LIVE.md:153-173.
   Required correction: describe first activation separately from active mode;
   do not promise universal reset or universal fail-open.

4. Missing rewrite metadata is legacy permission, not explicit denial.

   src/inspection_worker.py:161 gates only an explicit JSON false. Length-
   changing output is accepted when rewrite is absent. src/inspection.cpp:560
   also uses control.value("rewrite", true) for Translate eligibility; version 1
   and sequence 1 remain mandatory. This supports older strict-control peers
   without setup reservation, whereas H2_TRANSLATE_LIVE.md:9-18 describes
   rewrite=true plus setup as mandatory without naming this compatibility path.

   Worker reproduction with identical H1 input and `return api.bytes + b'x'`:
     {version: 1, sequence: 1}                  -> ok=true
     {version: 1, sequence: 1, rewrite: false}  -> CommitException

   Existing tests/inspection_translate_live_test.cpp:51-52 deliberately sends
   version/sequence/mode without rewrite and accepts Translate in that fixture.
   This is not evidence that every old proxy build supports the whole contract.

   Recommendation: keep ordinary legacy Rewrite compatibility if intended,
   document absent/false/true distinctly, and explicitly choose whether legacy
   strict-control Translate is supported or requires the new reservation.
   No silent tightening was made during this audit.

Reviewed contract / evidence map
--------------------------------
Setup and permission:
  Connection.request_rewrite() is setup-only, idempotent and staged.
  Worker rejects setup byte results. Failed setup does not publish permission.
  New proxy gates before input analysis; same-size raw replacement is an
  intentional exception and does not allocate an output context.
  tests/inspection_setup_test.py; proxy need_more_integration setup scenarios.

Easy versus Expert:
  Easy is the commit default; Expert is per call and does not survive hold.
  Expert relaxes specified semantic guards, not quotas, physical framing or
  Translate invariants. Supported Content-Digest and Content-Length repairs
  remain enabled. Raw script output is not a typed semantic safety boundary.
  tests/inspection_safety_test.py (separate Easy/Expert CTest registrations).

Commit atomicity:
  Snapshot and message assembly return private results; publication requires
  returning the result from the script. Failed commits can be corrected/retried.
  Translate stages encoder/settings/checkpoints and publishes only after checks.
  This is not rollback of storage writes or earlier successful script states
  across a chain; README.md:90-96 explicitly excludes those transactions.
  tests/inspection_api_test.py::test_failure_retry_and_injection;
  tests/inspection_h2_test.py::test_interleaved_streams_and_atomic_retry;
  tests/inspection_translate_worker_test.py::test_failed_assembly_retry_keeps_output_table_atomic.

Hold and lifecycle:
  Last enabled live flow deployment only; direction-specific backend checkpoints.
  Empty emitted prefix -> need-more; nonempty prefix -> replace. Worker restart
  is not backend restart. Stop/expiry/redeploy can discard ordinary held data.
  A resumed callback must return an explicit result. Ordinary hold failure and
  ordering protection remain acknowledged limitations, not newly discovered bugs.
  src/inspection_hold.py:320; src/inspection.cpp:306-328, :394-450;
  tests/inspection_hold_test.py; tests/inspection_hold_live_test.cpp.

Translate:
  First content callback, sole enabled flow deployment, explicit returned result
  for every callback. Active pin bypasses ordinary scope/filter selection, not
  the script. Input/output HPACK states and both directions remain distinct.
  Header translation and same-length DATA are supported; arbitrary length-
  changing DATA and general flow-control translation are not implemented.
  tests/inspection_translate_worker_test.py; tests/inspection_translate_live_test.cpp;
  tests/translate_e2e.py; docs/H2_TRANSLATE_LIVE.md.
